# Проверка шкалы оценок и радиуса

25 октября 2026 года. Живой Qloo, исходные профили из интерфейса:

- You: Blade Runner, Radiohead, Studio Ghibli.
- Partner: Metallica, Peaky Blinders, Guinness.

Собрано около 42 запросов: поиск интересов, 7 районов Цюриха при радиусах
1200 и 700 м для каждого участника, 4 района Алматы при 1500 м.
Расчёты чувствительности выполнены локально на одних и тех же ответах.
API-ключи в результаты не записывались. Исходные ответы сохраняются только
в игнорируемом `artifacts/scoring-audit-data.json`.

## Новая шкала

`score = 100 * (1 - (best - raw) / max(best - worst, MIN_SPREAD))`,
где `MIN_SPREAD = 0.08`. Отсутствующие данные остаются `null`.
При равенстве доступных значений все они получают 100 и предупреждение.
Group fit по-прежнему определяется самым низким личным результатом.

Порог предупреждения `LOW_SPREAD` приравнен к `MIN_SPREAD`. Это позволяет
показывать предупреждение всем участникам с растянутым ранее малым разбросом.

Наблюдаемые сырые разбросы:

| Город / радиус | You | Partner | Предупреждение |
| --- | ---: | ---: | --- |
| Zurich / 1200 м | 0.0390 | 0.0229 | Оба |
| Zurich / 700 м | 0.0567 | 0.0230 | Оба |
| Almaty / 1500 м | 0.0690 | 0.0215 | Оба |

Чувствительность худшей личной оценки к нижней границе знаменателя:

| Выборка / участник | 0.05 | 0.08 | 0.10 |
| --- | ---: | ---: | ---: |
| Zurich 700 м / You | 0 | 29 | 43 |
| Zurich 700 м / Partner | 54 | 71 | 77 |
| Almaty / You | 0 | 14 | 31 |
| Almaty / Partner | 57 | 73 | 79 |

0.05 сохраняет проблему нулей на этих профилях; 0.10 сглаживает сильнее.
0.08 оставлен как начальная явная эвристика: эти примеры подтверждают её
поведение, но не являются статистической калибровкой для любых пользователей.
При реальном разбросе >= 0.08 нулевые относительные оценки всё ещё возможны.

## Фактический формат location и why

У места Fraumünster Qloo вернул:

```json
{"location": {"lat": 47.3703943, "lon": 8.5418115, "geohash": "u0qj6rebw9u8"}}
```

`location` находится на верхнем уровне сущности. Формат пригоден для будущей
привязки к ближайшему центру до расчёта районных средних.

`query.explainability`, сохраняемый в `evidence.why`, имеет вид:

```json
{"signal.interests.entities": [{"entity_id": "<Qloo input ID>", "score": 0.3517726980692226}]}
```

В живом ответе было три входных ID с весами. Имена любимых объектов внутри
этого поля отсутствуют. Ночной интерфейс журналирует один исходный `why`
через `console.log`, рисует реальные связи с ID и не подставляет названия
по догадке. При отсутствии поддерживаемых связей остаётся район → места → теги.

## Теги и проверки

Служебные теги удаляются до выбора первых пяти названий. Набор исключений
учитывает способы оплаты, доступность, парковку, цены, доставку, Wi-Fi,
прачечные и служебные правила заказа. Границы слов сохраняют, например,
`Improvisation` и `Cashmere`; повторяющиеся теги объединяются без учёта регистра.

Очищенные теги используются в evidence, то есть в карточках, SVG-графе и
запросе объяснения Gemini. Сырые affinity и explainability не изменяются.

Автоматические проверки: **35 passed**. Включены маленькие и большие разбросы,
равные значения, отсутствие данных, групповой минимум, служебные теги за
пределами первых пяти позиций и фактическое содержимое запроса к LLM.
